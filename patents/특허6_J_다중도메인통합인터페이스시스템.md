# 특허출원서

## 【서지사항】

**【발명의 명칭】**
다중 도메인 통합 인터페이스 시스템 및 데이터 교환 방법

**【발명의 영문명칭】**
Multi-Domain Integration Interface System and Data Exchange Method

---

## 【명세서】

### 【발명의 명칭】
다중 도메인 통합 인터페이스 시스템 및 데이터 교환 방법

### 【기술분야】
본 발명은 이종(異種) 도메인 간의 데이터 교환 및 통합에 관한 기술로서, 특히 서로 다른 데이터 구조, 프로토콜, 의미 체계를 갖는 복수의 도메인 시스템을 단일 인터페이스를 통해 연결하고, 도메인 간 데이터 변환 및 라우팅을 수행하는 통합 인터페이스 시스템에 관한 것이다.

### 【발명의 배경이 되는 기술】
현대의 기업 환경에서는 ERP, CRM, SCM, MES 등 다양한 도메인별 시스템이 운영되고 있으며, 이들 시스템 간의 데이터 교환이 필수적이다. 그러나 각 시스템은 고유한 데이터 구조, 통신 프로토콜, 의미 체계를 가지고 있어 직접적인 연동이 어렵다.

기존 시스템 간 연동 방식의 기술적 한계는 다음과 같다:

첫째, 점대점(Point-to-Point) 연동 방식은 시스템 수가 증가함에 따라 연동 복잡도가 기하급수적으로 증가한다 (N개 시스템 연동 시 N×(N-1)/2개의 연동 필요).

둘째, 각 시스템의 데이터 구조 변경 시 모든 관련 연동을 개별적으로 수정해야 한다.

셋째, 도메인 간 의미 체계의 차이로 인해 동일한 개념이 다르게 표현되어 데이터 불일치가 발생한다.

넷째, 연동 현황의 가시성이 부족하여 문제 발생 시 원인 파악이 어렵다.

다섯째, 새로운 시스템 추가 시 기존 연동 구조에 영향을 주지 않고 통합하기 어렵다.

따라서 복수의 이종 도메인을 단일 인터페이스로 통합하고, 도메인 간 데이터 변환을 자동화하며, 연동 구조의 확장성을 보장하는 기술이 요구된다.

### 【발명의 내용】

#### 【해결하고자 하는 과제】
본 발명은 상기한 종래 기술의 문제점을 해결하기 위하여 안출된 것으로서, 다음과 같은 기술적 과제를 해결하고자 한다.

첫째, 복수의 이종 도메인 시스템을 단일 통합 인터페이스에 연결하여 연동 복잡도를 선형으로 감소시키는 기술을 제공한다.

둘째, 도메인별 데이터 구조를 표준화된 공통 데이터 모델로 변환하는 기술을 제공한다.

셋째, 도메인 간 의미 체계 매핑을 통해 데이터 일관성을 보장하는 기술을 제공한다.

넷째, 데이터 교환 규칙에 따라 적절한 대상 도메인으로 데이터를 라우팅하는 기술을 제공한다.

다섯째, 연동 현황 및 데이터 흐름을 실시간으로 모니터링하는 기술을 제공한다.

#### 【과제의 해결 수단】
상기 과제를 해결하기 위하여 본 발명에 따른 다중 도메인 통합 인터페이스 시스템은 다음을 포함한다:

복수의 도메인 시스템과 개별적으로 연결되어, 각 도메인의 고유 프로토콜을 통해 데이터를 송수신하는 복수의 도메인 어댑터(Domain Adapter);

상기 도메인 어댑터로부터 수신된 도메인별 데이터를 표준화된 공통 데이터 모델(CDM: Common Data Model)로 변환하고, 역으로 공통 데이터 모델을 대상 도메인의 형식으로 변환하는 데이터 변환 엔진(Data Transformation Engine);

도메인 간의 개념적 매핑 정보를 저장하고, 상기 데이터 변환 엔진의 변환 과정에서 의미 체계 매핑을 지원하는 시맨틱 매핑 저장소(Semantic Mapping Repository);

기설정된 라우팅 규칙에 따라 변환된 데이터를 적절한 대상 도메인으로 전달하는 라우팅 엔진(Routing Engine); 및

도메인 간 데이터 교환 현황, 변환 이력, 오류 발생 내역을 실시간으로 모니터링하는 통합 모니터링부(Integration Monitor);를 포함한다.

본 발명의 일 실시예에 따르면, 상기 공통 데이터 모델(CDM)은 다음의 구조를 갖는다:

```
CommonDataModel = {
    message_id: UUID,                   // 메시지 고유 식별자
    source_domain: STRING,              // 원천 도메인
    target_domains: LIST[STRING],       // 대상 도메인(들)
    message_type: STRING,               // 메시지 유형
    timestamp: ISO8601,                 // 생성 시점
    payload: {
        entities: LIST[Entity],         // 표준화된 엔티티 목록
        relationships: LIST[Relation]   // 엔티티 간 관계
    },
    metadata: {
        transformation_applied: LIST,   // 적용된 변환 이력
        routing_path: LIST              // 라우팅 경로
    }
}
```

#### 【발명의 효과】
본 발명에 따르면 다음과 같은 효과를 얻을 수 있다.

첫째, 허브-스포크(Hub-Spoke) 구조를 통해 N개 시스템 연동 시 N개의 어댑터만 필요하여 연동 복잡도가 선형으로 감소한다.

둘째, 공통 데이터 모델을 통해 도메인별 데이터 구조 변경이 다른 도메인에 영향을 주지 않는다.

셋째, 시맨틱 매핑을 통해 도메인 간 의미 체계 차이로 인한 데이터 불일치를 방지한다.

넷째, 라우팅 엔진을 통해 데이터가 적절한 대상 도메인으로 자동 전달된다.

다섯째, 새로운 도메인 시스템 추가 시 해당 어댑터만 개발하면 되어 확장이 용이하다.

### 【도면의 간단한 설명】
**【도 1】** 본 발명에 따른 다중 도메인 통합 인터페이스 시스템의 전체 구성을 나타내는 블록도이다.

**【도 2】** 점대점 연동 방식과 본 발명의 허브-스포크 방식을 비교하는 도면이다.

**【도 3】** 데이터 변환 엔진의 변환 프로세스를 나타내는 플로우차트이다.

**【도 4】** 시맨틱 매핑 저장소의 구조를 나타내는 도면이다.

**【도 5】** 라우팅 엔진의 라우팅 규칙 처리 과정을 나타내는 도면이다.

### 【발명을 실시하기 위한 구체적인 내용】

이하, 첨부된 도면을 참조하여 본 발명의 바람직한 실시예를 상세히 설명한다.

#### [시스템 구성]

도 1을 참조하면, 본 발명에 따른 다중 도메인 통합 인터페이스 시스템(5000)은 복수의 도메인 어댑터(5100), 데이터 변환 엔진(5200), 시맨틱 매핑 저장소(5300), 라우팅 엔진(5400), 및 통합 모니터링부(5500)를 포함한다.

도메인 어댑터(5100)는 각 도메인 시스템의 고유 프로토콜(REST API, SOAP, 메시지 큐, 파일 전송 등)을 지원하여 데이터를 송수신한다. 각 어댑터는 해당 도메인의 데이터 구조를 이해하고, 내부 공통 형식과의 초기 변환을 수행한다.

데이터 변환 엔진(5200)은 도메인 어댑터로부터 수신된 데이터를 공통 데이터 모델(CDM)로 변환한다. 변환 과정에서 시맨틱 매핑 저장소(5300)를 참조하여 도메인 간 개념 매핑을 적용한다. 역으로, 대상 도메인으로 데이터를 전송할 때는 CDM을 해당 도메인의 형식으로 변환한다.

시맨틱 매핑 저장소(5300)는 도메인 간의 개념적 매핑 정보를 저장한다. 예를 들어, ERP 시스템의 "Customer_ID"와 CRM 시스템의 "Account_Number"가 동일한 개념임을 매핑한다.

라우팅 엔진(5400)은 기설정된 라우팅 규칙에 따라 데이터를 적절한 대상 도메인으로 전달한다. 라우팅 규칙은 메시지 유형, 내용, 원천 도메인 등에 기반하여 정의될 수 있다.

통합 모니터링부(5500)는 전체 데이터 교환 현황을 실시간으로 모니터링한다. 데이터 흐름, 변환 성공/실패, 라우팅 경로, 처리 시간 등의 지표를 제공한다.

#### [실시예 1: 제조 기업의 시스템 통합]

본 실시예에서 다중 도메인 통합 인터페이스 시스템은 제조 기업의 ERP, MES, SCM, QMS 시스템을 통합하는 데 적용된다.

연결 대상 도메인:
- ERP (Enterprise Resource Planning): SAP 기반, RFC 프로토콜
- MES (Manufacturing Execution System): 자체 개발, REST API
- SCM (Supply Chain Management): 클라우드 SaaS, 웹훅
- QMS (Quality Management System): 레거시, 파일 전송

각 도메인별 어댑터가 개발되어 통합 인터페이스에 연결된다.

시맨틱 매핑 예시:
- ERP.Material_Number ↔ MES.Part_ID ↔ SCM.SKU ↔ QMS.Item_Code
- ERP.Production_Order ↔ MES.Work_Order ↔ SCM.Manufacturing_Request

라우팅 규칙 예시:
- "생산 완료" 메시지 → ERP (재고 업데이트) + SCM (출하 준비)
- "품질 이상" 메시지 → QMS (품질 기록) + MES (공정 중단)

이 구성에서 MES에서 생산 완료 이벤트가 발생하면:
1. MES 어댑터가 이벤트를 수신
2. 데이터 변환 엔진이 MES 형식을 CDM으로 변환
3. 라우팅 엔진이 "생산 완료" 규칙에 따라 ERP와 SCM을 대상으로 결정
4. 데이터 변환 엔진이 CDM을 ERP 형식과 SCM 형식으로 각각 변환
5. 각 도메인 어댑터가 변환된 데이터를 대상 시스템으로 전송

#### [실시예 2: 이커머스 플랫폼 통합]

본 실시예에서 다중 도메인 통합 인터페이스 시스템은 이커머스 플랫폼의 주문, 결제, 물류, 고객서비스 시스템을 통합하는 데 적용된다.

연결 대상 도메인:
- 주문 시스템: 자체 개발, GraphQL
- 결제 시스템: PG사 연동, REST API
- 물류 시스템: 3PL 연동, EDI
- 고객서비스 시스템: CRM, SOAP

라우팅 규칙 예시:
- "주문 확정" 메시지 → 결제 (결제 요청) + 물류 (배송 준비)
- "결제 완료" 메시지 → 주문 (상태 업데이트) + 고객서비스 (확인 메일)
- "배송 완료" 메시지 → 주문 (상태 업데이트) + 고객서비스 (리뷰 요청)

#### [실시예 3: 헬스케어 의료 시스템 통합]

본 실시예에서 다중 도메인 통합 인터페이스 시스템은 병원의 다양한 의료 시스템을 통합하는 데 적용된다.

연결 대상 도메인:
- EMR (전자의무기록): HL7 FHIR 기반, REST API
- PACS (의료영상): DICOM 프로토콜
- LIS (검사정보시스템): HL7 v2 메시지
- 약국 시스템: 자체 개발, TCP/IP 소켓
- 보험청구 시스템: EDI
- 환자 포털: 웹 기반, GraphQL

각 도메인별 어댑터가 개발되어 통합 인터페이스에 연결된다.

시맨틱 매핑 예시:
- EMR.Patient_ID ↔ PACS.PatientKey ↔ LIS.PID ↔ 약국.환자번호
- EMR.Diagnosis_Code ↔ 보험청구.상병코드 (ICD-10 매핑)
- LIS.Test_Code ↔ 보험청구.검사코드 (EDI 코드 매핑)

라우팅 규칙 예시:
- "검사 처방" 메시지 → LIS (검사 접수) + 보험청구 (수가 산정)
- "검사 결과 확정" 메시지 → EMR (결과 기록) + 환자포털 (결과 알림)
- "퇴원 처리" 메시지 → 약국 (퇴원 처방) + 보험청구 (청구서 생성) + 환자포털 (퇴원 안내)

이 구성에서 의사가 EMR에서 검사를 처방하면:
1. EMR 어댑터가 처방 데이터를 수신
2. 데이터 변환 엔진이 HL7 FHIR 형식을 CDM으로 변환
3. 시맨틱 매핑을 통해 검사 코드가 LIS 코드 및 보험 코드로 변환
4. 라우팅 엔진이 LIS와 보험청구 시스템을 대상으로 결정
5. 각 대상에 맞는 형식(HL7 v2, EDI)으로 변환 후 전송

#### [실시예 4: 물류 통합 플랫폼]

본 실시예에서 다중 도메인 통합 인터페이스 시스템은 물류 기업의 다양한 시스템을 통합하는 데 적용된다.

연결 대상 도메인:
- OMS (주문관리시스템): 자체 개발, REST API
- WMS (창고관리시스템): 패키지 솔루션, SOAP
- TMS (배송관리시스템): SaaS, 웹훅
- 배송사 시스템: 복수 (CJ, 한진, 로젠 등), 각기 다른 API
- 판매 채널: 복수 (자사몰, 쿠팡, 네이버 등), 각기 다른 API
- ERP: SAP, RFC
- BI 시스템: 데이터 웨어하우스 연동

각 도메인별 어댑터가 개발되어 통합 인터페이스에 연결된다.

시맨틱 매핑 예시:
- OMS.Order_No ↔ WMS.Receipt_No ↔ TMS.Shipment_No ↔ 배송사.송장번호
- 쿠팡.Product_ID ↔ 네이버.상품코드 ↔ 자사몰.SKU ↔ WMS.Item_Code
- OMS.배송방법 ↔ TMS.서비스유형 (익일배송→일반, 새벽배송→새벽, 당일배송→퀵)

라우팅 규칙 예시:
- "신규 주문" 메시지 → OMS (주문 등록) + WMS (출고 지시)
- "출고 완료" 메시지 → TMS (배송 접수) + 판매채널 (상태 업데이트)
- "배송 완료" 메시지 → OMS (주문 완료) + 판매채널 (완료 처리) + ERP (매출 기록) + BI (데이터 적재)

이 구성에서 쿠팡에서 신규 주문이 들어오면:
1. 쿠팡 어댑터가 주문 데이터를 수신
2. 데이터 변환 엔진이 쿠팡 형식을 CDM으로 변환
3. 시맨틱 매핑을 통해 상품 코드, 배송 방법 등이 내부 코드로 변환
4. 라우팅 엔진이 OMS, WMS를 대상으로 결정
5. 각 대상에 맞는 형식으로 변환 후 전송
6. WMS에서 재고 할당 후 피킹 지시가 자동 생성

복수의 판매 채널과 복수의 배송사를 단일 통합 인터페이스로 연결함으로써, 채널/배송사 추가 시 해당 어댑터만 개발하면 된다.

#### [입출력 어댑터에 관한 사항]

본 발명의 도메인 어댑터, 프로토콜, 데이터 형식 등은 운영 환경에 따라 다양하게 구성될 수 있으며, 이는 본 발명의 핵심 기술적 특징인 "도메인 어댑터 → 데이터 변환 → 시맨틱 매핑 → 라우팅"의 프로세스를 벗어나지 않는 범위에서 운영상 결정되는 사항이다.

### 【산업상 이용가능성】
본 발명은 복수의 이종 시스템 통합이 필요한 제조, 유통, 금융, 헬스케어, 공공 등 다양한 산업 분야에 적용 가능하다. 특히 레거시 시스템과 신규 시스템의 공존, 클라우드와 온프레미스의 하이브리드 환경에서 유용하다.

### 【부호의 설명】
